## v1 当前实现策略（2026-08-31）

### 模型结构

- 使用 PyTorch Pi05，基础权重从 `pi05_base_pytorch` 加载。
- 保留 PaliGemma、视觉 SigLIP 和 Action Expert，并新增独立的 Tactile Expert。
- Tactile Expert 在基础 Action Expert 权重加载完成后复制初始化；Transformer 和 output head
  使用独立 storage，不共享可训练参数。
- AnyTouch2 左右各输出 36 个 token，共 72 个 token；只进入 Tactile Expert，不进入
  PaliGemma 的视觉语言 prefix。
- AnyTouch2 使用 `512 -> 1024` projector，backbone 和 projector 均参与 full fine-tuning。
- 所有模型参数默认参与更新：PaliGemma、RGB SigLIP、Action Expert、Tactile Expert、
  AnyTouch2 和 projector。

### Flow matching 与训练

- Action Expert 的训练时间采样覆盖 `(0, 1]`，训练目标为 `epsilon - action_gt`。
- Tactile Expert 的训练时间采样为 `0.4 * Beta(1.5, 1.0)`，范围为 `(0, 0.4]`，目标形式相同。
- 每个 batch 独立采样两组 noise 和时间，损失为：

  ```text
  total_loss = action_loss + tactile_loss
  ```

- Tactile loss 前先执行一次无梯度的 Action Expert 六步 slow pass，生成 `tau=0.4` 的
  detached boundary KV；该 loss 不回传到 PaliGemma 或 Action Expert。
- 训练日志分别记录 action loss、tactile loss、total loss 以及两路 velocity 的绝对值均值。
- global batch 为 `64`，四卡 DDP 每卡 `16`，不使用 gradient accumulation。

### 同步推理与 KV cache

- 单次请求内固定执行 Action Expert 六步（`1.0 -> 0.4`），再执行 Tactile Expert 四步
  （`0.4 -> 0.0`）。最终 action 是 Tactile Expert 的积分结果，不叠加 residual。
- Action-only fallback 关闭 Tactile Expert 时，由 Action Expert 独立完成完整十步采样。
- 推理时 RGB/language prefix 只编码一次并缓存 KV；每个 Euler step 重新计算当前 action suffix。
- 级联推理在 `tau=0.4` 刷新 boundary action KV，四个 tactile step 都从固定 boundary
  cache 开始，不累积上一步的 tactile suffix。
- KV cache 是推理优化，不是 VLA 必需机制；关闭 cache、每步重算 prefix 在语义上仍然成立，
  但速度更慢。
- 训练的常规有梯度 forward 使用 `gradient checkpointing` 且不使用 KV；只有 detached
  slow pass 临时关闭 checkpointing 以生成 boundary KV。

### 数据与 serving

- 数据继续复用已有 LeRobot 单帧 tactile 数据和 norm stats；训练 loader lazy 取
  `[t-6, t-4, t-2, t]`，不跨 episode。
- serving 继续使用 strict-clip 协议：左右触觉均为 contiguous RGB `uint8[4,224,224,3]`，
  帧顺序为 oldest -> newest。
- server 不维护跨请求 tactile history、`x_split` 或 KV；所有级联步骤在一次请求内同步完成。
- metadata 标记 `anytouch2_cascaded_expert`、clip offsets `[-6,-4,-2,0]` 和 `6+4` dispatch。

### 配置与启动

- 新配置后缀为
  `vision_tactile_anytouch2_tactile_expert_torch_full_ft`，W&B project 为
  `openpi-anytouch-trex`。
- 已为 Insert USB V3、Insert Block V1/V2、Hardness Classify、Pull Drawer、Turn Gear Pair、
  Weight Classify、Roughness Regrasp 和 Roughness Classify 配置独立任务入口。
- 共享 launcher 只复用已有数据和 norm stats，训练前检查基础权重、AnyTouch 权重和四卡显存；
  显存任一卡不满足 `<20000 MiB` 时每 30 秒轮询。
- launcher 支持 `DRY_RUN`、`RESUME`、显存阈值、GPU 列表和训练步数覆盖，并在启动前生成脚本快照。
- T-Rex 共享 launcher 和九个任务入口统一放在 `scripts/train/t-rex/`。
- T-Rex checkpoint 默认写入 `checkpoints/t-rex/<config>/<experiment>/<step>`，与普通 OpenPI
  checkpoint 分目录保存；可通过 `CHECKPOINT_BASE_DIR` 覆盖。

### v1 范围边界

- 首版不实现异步 slow/fast 请求、offset、delay augmentation、跨请求 cache 或 tactile residual。
- 首版从干净 `pi05_base_pytorch` 初始化，不迁移旧 AnyTouch task checkpoint。
- 普通 vision、dual-SigLIP 和旧 AnyTouch prefix 配置保持原行为。
- 正式 10k/20k 训练由 launcher 负责；当前实现阶段只完成结构、配置、脚本和聚焦测试验证。

## 1. 目标

在现有 PyTorch Pi05 模型上增加第三条 Transformer 分支：

```text
PaliGemma / RGB-language expert
             ↓ cached visual-language KV
Action Expert：负责前 6 个 flow-matching Euler steps
             ↓ x_split + boundary action KV at τ=0.4
Tactile Expert：读取 AnyTouch2 的 72 个 tactile tokens，负责后 4 个 Euler steps
             ↓
final action chunk
```

计划保持：

```text
total denoising steps   10
Action Expert steps      6, τ: 1.0 -> 0.4
Tactile Expert steps     4, τ: 0.4 -> 0.0
τ_split                  0.4
flow integrator          Euler, Δτ = -0.1
action horizon           继续使用 OpenPI 当前的 50
tactile history          [t-6, t-4, t-2, t]
tactile tokens           left 36 + right 36 = 72
```

本版本只做单次请求内的**同步串行级联**，不实现 T-Rex 的异步 slow/fast runtime。

## 2. T-Rex 原论文的关键机制

T-Rex 并不是先得到完整 action，再让 tactile 网络输出一个 residual。它把同一条
flow-matching 轨迹切成两个区间：

```text
Action Expert  : τ ∈ [0.4, 1.0]
Tactile Expert : τ ∈ [0.0, 0.4]
```

给定示范 action `A` 和 Gaussian noise `ε`：

```text
x_τ = (1 - τ) A + τ ε
v*  = ε - A
```

两个 expert 预测相同的 velocity target `v*`，只是在不同的时间区间、不同的条件下学习：

```text
L_action  = MSE(ActionExpert(x_τ_action, τ_action; visual-language), v*)
L_tactile = MSE(TactileExpert(x_τ_tactile, τ_tactile; tactile, detached KV_split), v*)
```

论文设置：

```text
τ_action  ~ Beta(1.5, 1.0), mapped to (0, 1]
τ_tactile = 0.4 * Beta(1.5, 1.0), mapped to (0, 0.4]
λ_tactile = 1.0
```

因此 Tactile Expert 的积分结果本身就是最终 action chunk：

```text
final_action = Euler(TactileExpert, x_split, τ: 0.4 -> 0.0)
```

不能实现成：

```text
final_action = action_expert_output + tactile_residual
```

论文还保留 Action Expert 在完整 `(0, 1]` 上的训练，使其在触觉缺失时仍可独立完成全部
10 步采样。这个性质也建议保留在 OpenPI 版本中。

## 3. 与论文版本的差异

### 3.1 不做异步推理

T-Rex 原版会：

- 低频运行 Action Expert，并保存 `x_split` 与 `KV_split`。
- 在一个 action chunk 内多次读取新触觉，异步重新运行后 4 步 Tactile Expert。
- 训练时对触觉加入 `{0,4,8,12}` 的 delay augmentation，以模拟视觉 cache 的时间陈旧。

本计划面向仿真，先使用更简单的同步路径：

```text
一次 infer 请求
  -> 当前 RGB、language 运行一次
  -> Action Expert 连续运行 6 步
  -> 当前 [t-6,t-4,t-2,t] tactile clip 运行 AnyTouch2
  -> Tactile Expert 连续运行 4 步
  -> 返回 action chunk
```

因此 v1 不需要：

- slow/fast 两类 websocket 请求；
- server 跨请求保存 `x_split` 或 KV cache；
- 并行线程、锁或异步调度；
- intra-chunk offset；
- delay augmentation。

需要注意：不做异步后，触觉只在每次 policy 请求时更新。如果 client 一次开环执行很多动作，
它不会在 chunk 中途根据新触觉重算。要获得更强的 tactile-reactive 效果，应缩短
`open_loop_horizon`；最直接的对照实验是设为 `1` 或较小值。

### 3.2 Tactile Expert 使用 Action Expert 复制初始化

T-Rex 当前开源 post-train 代码在从 tactile-free checkpoint 启动时，会重新初始化 tactile
expert；它不是简单复制 Action Expert。

本计划按当前实验设想，明确采用：

```python
tactile_expert = deepcopy(action_expert)
tactile_action_out_proj = deepcopy(action_out_proj)
```

复制必须发生在 Pi05 base/action 权重加载完成之后，不能在加载 base 权重之前复制随机初始化参数。
后续从已经包含 Tactile Expert 的完整 checkpoint resume 时，则直接加载 tactile 权重，不再重复复制。

## 4. 建议的 OpenPI 模型结构

当前 PyTorch OpenPI 是：

```text
PaliGemmaWithExpertModel
  ├── paligemma.language_model   # RGB + language context
  └── gemma_expert               # action suffix, gemma_300m
```

建议扩展为：

```text
PaliGemmaWithExpertModel
  ├── paligemma.language_model
  ├── gemma_expert
  └── gemma_tactile_expert       # deepcopy(gemma_expert)

PI0Pytorch
  ├── action_in_proj             # action -> 1024，可由两个 expert 共享
  ├── time_mlp_*                 # time -> adaRMS condition，可共享
  ├── action_out_proj            # Action Expert velocity head
  ├── tactile_action_out_proj    # 独立复制的 tactile velocity head
  └── anytouch2_encoder
        ├── AnyTouch2 backbone
        └── late projector 512 -> 1024
```

这里的 `1024` 来自当前 `gemma_300m` Action Expert width。现有 AnyTouch prefix 版本使用
`512 -> 2048` projector，因为 token 会进入 PaliGemma prefix；新版本的 tactile token 进入
Tactile Expert，所以不能直接复用旧 projector 的形状。

v1 建议共享 `action_in_proj` 和 `time_mlp_*`，但使用独立的 Tactile Expert Transformer 与
`tactile_action_out_proj`。这与 T-Rex“共享 flow 表示、独立 expert/head”的思路更接近，也比
复制所有小投影层更节省参数。后续可以将全部 suffix adapter 独立作为消融实验。

### 4.1 为什么不需要把三路 expert 强行放进一次 joint forward

当前 OpenPI 已经支持：

- PaliGemma 单独生成 prefix KV；
- Action Expert 使用 prefix KV 做 suffix forward。

Tactile Expert 可以复用同一模式：

1. PaliGemma 生成 RGB/language KV。
2. Action Expert 运行前 6 步并在 `τ=0.4` 刷新 action KV。
3. Tactile Expert 使用 `[visual-language KV | boundary action KV]` 继续运行。

这样只需给 `PaliGemmaWithExpertModel` 增加第三个 Gemma model，并实现 cache crop/clone/refresh，
不需要先重写整个两专家 joint-attention 训练实现。

## 5. Token 与 KV 的准确顺序

新版本中 AnyTouch 不再属于 PaliGemma prefix。Action Expert 的上下文中不包含 tactile token。

Action Expert 前 6 步的逻辑上下文：

```text
[base SigLIP tokens -> wrist SigLIP tokens -> language tokens]
                                  ↓ cached prefix KV
[noisy action tokens，flow timestep 通过 Pi05 adaRMS condition 注入]
```

在 `τ=0.4`，用当前的 `x_split` 重新编码一次 action suffix，得到 coherent boundary cache：

```text
KV_split = [RGB/language KV | action KV at τ=0.4]
```

Tactile Expert 每一步追加的 token 顺序：

```text
left AnyTouch 36
-> right AnyTouch 36
-> current noisy/partial action tokens
```

因此“前 72 个 token 是 AnyTouch”指的是 **Tactile Expert 当前追加序列**的前 72 个 token。
从整个 KV 的全局顺序看，视觉、语言和 boundary action cache 已经存在于它们之前：

```text
[cached RGB/language | cached boundary action]
-> [left tactile 36 | right tactile 36 | time | action]
```

这种顺序保证 Tactile Expert 的 action tokens 可以 attend 到 72 个 tactile tokens，同时不需要重新
运行 SigLIP 或 PaliGemma。

## 6. 同步推理流程

默认总步数为 10：

```text
initial x = Gaussian noise

Action Expert:
  τ=1.0, 0.9, 0.8, 0.7, 0.6, 0.5
  each: x <- x - 0.1 * v_action
  result: x_split at τ=0.4

refresh boundary action KV using x_split and τ=0.4

AnyTouch2:
  left  [t-6,t-4,t-2,t] -> 36 tokens
  right [t-6,t-4,t-2,t] -> 36 tokens

Tactile Expert:
  τ=0.4, 0.3, 0.2, 0.1
  each: x <- x - 0.1 * v_tactile
  result: final action at τ=0.0
```

每个 Tactile Expert step 都从固定的 boundary cache clone 开始，移除上一步临时追加的 tactile
suffix，再用当前 `x` 和 `τ` 重新追加。不能让四步的 tactile suffix 在 cache 中不断累积。

建议保留一个 Action-Expert-only inference 分支，用 10 步 Action Expert 完成采样，作为：

- 无 tactile baseline；
- tactile 缺失时 fallback；
- 验证新增架构没有破坏原 Pi05 的回归路径。

## 7. 训练流程

一个 batch 需要两项 loss。

### 7.1 Action Expert loss

沿用当前 Pi05 flow-matching 训练：

```text
τ_action ~ Beta(1.5, 1.0) over (0,1]
x_action = (1-τ_action) * action_gt + τ_action * ε_action
v_target = ε_action - action_gt
L_action = MSE(v_action, v_target)
```

Action Expert 只读取：

```text
base RGB + wrist RGB + language/state prompt
```

不能读取 AnyTouch token，否则 slow 分支不再是 tactile-blind，且部署时无法跳过 AnyTouch。

### 7.2 Detached boundary cache

为了让 Tactile Expert 看到与推理一致的上下文，需要在训练 batch 内执行一次 detached slow pass：

```text
with torch.no_grad():
    x_split, kv_split = action_expert_partial_sample(
        fresh_noise,
        total_steps=10,
        action_steps=6,
        refresh_boundary_kv=True,
    )
```

`kv_split` 必须 detach；`L_tactile` 不回传到 PaliGemma 或 Action Expert。PaliGemma 与 Action
Expert 由 `L_action` 更新。

这一步会额外执行 6 次无梯度 Action Expert forward，是新版本训练时间的主要开销。

### 7.3 Tactile Expert loss

独立采样 tactile 区间的 flow time 和 noise：

```text
τ_tactile = 0.4 * Beta(1.5, 1.0)
x_tactile = (1-τ_tactile) * action_gt + τ_tactile * ε_tactile
v_target_tactile = ε_tactile - action_gt

tactile_tokens = AnyTouch2(left_clip, right_clip)  # 72 tokens
v_tactile = TactileExpert(x_tactile, τ_tactile, tactile_tokens, detached kv_split)
L_tactile = MSE(v_tactile, v_target_tactile)
```

OpenPI 没有 T-Rex 的 future-frame latent prediction loss，所以初版总 loss 只需：

```text
L = L_action + λ_tactile * L_tactile
λ_tactile = 1.0
```

建议单独记录：

```text
train/action_loss
train/tactile_loss
train/total_loss
train/action_velocity_abs_mean
train/tactile_velocity_abs_mean
```

## 8. AnyTouch2 与数据路径

数据格式不需要变化，继续在 LeRobot 中只存单帧 tactile：

```text

right_tactile_image  uint8 [224,224,3]
```

训练 loader 继续 lazy 读取：

```text

```

并严格限制在同一 episode；开头不足时重复 episode 第一帧。本版本不做 offset，也不做随机 delay。

AnyTouch 输入预处理继续使用固定 CLIP mean/std。普通 RGB 继续使用 OpenPI 的 `[-1,1]`。
state/action 表达不变时可以继续复用已有 norm stats；不需要为新增 Tactile Expert 重算。

### 8.1 AnyTouch 全量微调

本实现按首版实验设定，对 AnyTouch2 backbone 和 projector 都进行全量微调：

```text
AnyTouch2 backbone          trainable
AnyTouch 512 -> 1024 proj   trainable
Tactile Expert              trainable
PaliGemma / SigLIP          trainable through L_action
Action Expert               trainable through L_action
```

随后再做 `anytouch_trainable=True` 的对照。如果希望完全延续当前 AnyTouch full-FT 习惯，也可以
直接训练 backbone，但四卡 DDP 显存和训练时间风险都会明显增加。

## 9. 权重初始化与 checkpoint 兼容

### 9.1 推荐的首个实验初始化

最干净的 v1 起点是：

```text
Pi05 / PaliGemma / Action Expert <- pi05_base_pytorch
AnyTouch2 backbone               <- checkpoint-4frames.pth
Tactile Expert Transformer       <- copy loaded Action Expert
Tactile output head              <- copy loaded action_out_proj
AnyTouch 512 -> 1024 projector   <- new initialization
```

这样 Action Expert 从一开始就是 tactile-blind，不会依赖旧版本的 tactile prefix。

### 9.2 迁移已有 AnyTouch full-FT checkpoint

现有 task checkpoint 也可以作为初始化源，但需要显式迁移：

```text
load PaliGemma / SigLIP / Action Expert
load AnyTouch2 backbone
discard old AnyTouch 512 -> 2048 projector
stop inserting tactile into PaliGemma prefix
copy the loaded Action Expert into Tactile Expert
initialize new 512 -> 1024 projector
```

风险是旧 Action Expert 在训练时始终能看到 tactile prefix；去掉该 prefix 后会发生条件分布变化。
因此建议先用 base checkpoint 完成结构正确性实验，再比较“从旧 AnyTouch task checkpoint 迁移”。

### 9.3 加载规则

需要区分两类 checkpoint：

```text
base/legacy checkpoint:
  允许缺失 gemma_tactile_expert、tactile_action_out_proj、late AnyTouch projector
  base 加载完成后执行一次 copy initialization

new full checkpoint:
  要求完整加载所有 tactile expert 参数
  不再执行 copy initialization
```

保存时必须确保 Action Expert 与 Tactile Expert 是独立参数，不能因为错误的 module 引用而共享
同一块 storage。

## 10. Serving 协议

本版本可以继续使用当前 strict-clip 请求：

```python
{
    "observation/state": float32_array,                  # [8]
    "observation/image": uint8_array,                    # [224,224,3]
    "observation/wrist_image": uint8_array,              # [224,224,3]
    "observation/left_tactile_clip": uint8_array,        # [4,224,224,3]
    "observation/right_tactile_clip": uint8_array,       # [4,224,224,3]
    "prompt": str,
    "reset": True,                                       # episode first request only

```

clip 顺序仍为 oldest -> newest，即 `[t-6,t-4,t-2,t]`。无需新增 slow/fast mode，也无需 server
维护跨请求 tactile history 或 boundary KV。


### Training

`scripts/train_pytorch.py`

- 支持一个 batch 返回 `action_loss + tactile_loss`。
- detached slow pass 在训练中构造 boundary cache。
- W&B 分别记录两项 loss。
- base checkpoint 部分加载后复制 Action Expert。
- resume 新 checkpoint 时完整恢复三个 expert 和 optimizer。
- optimizer 只包含 `requires_grad=True` 参数。

### Data / policy / serve

现有 lazy history、`TactileClipPolicy` 和 strict-clip payload 可以复用。主要需要确保新 config 在
`policy_config.py` 仍选择 strict-clip wrapper，并且模型内部不再把 tactile keys 分发到 prefix。

## 12. 训练与显存风险

当前 PyTorch trainer 使用 DDP，不是参数分片；四张 GPU 上每张都会保存完整模型与 optimizer。
复制 `gemma_300m` 会在每张卡上增加一份 Expert 参数和 optimizer state，而训练时还多出：

- 每 batch 6 次 detached Action Expert forward；
- 1 次带梯度 Tactile Expert forward；
- 72 个 AnyTouch token；
- Tactile Expert activation 与 gradient。

当前 launcher 固定 global batch 64、四卡 DDP、每卡 16，不自动降 batch 或使用梯度累积。
若显存不足会直接由训练进程报错；正式长训前仍建议先做短 smoke test：

```text
1. batch 4，单步 forward/backward
2. batch 16，运行 20 steps
3. batch 32，观察峰值显存和吞吐
4. 确认有余量后再尝试 global batch 64
```

Tactile Expert 已启用 gradient checkpointing；本版本不实现自动降 batch 或 gradient accumulation。

## 13. 验证清单

### Architecture

- base checkpoint 加载后，Tactile Expert 与 Action Expert 参数逐项相等。
- 两个 expert 参数 storage 独立；更新 Tactile Expert 不改变 Action Expert。
- 完整 tactile checkpoint resume 时不重新复制。
- AnyTouch 每侧输出 36 token，总计 72 token，最后维度为 1024。
- Action Expert prefix 中不存在 tactile token。

### Training

- `τ_action ∈ (0,1]`，`τ_tactile ∈ (0,0.4]`。
- 两项 loss 使用相同形式的 flow velocity target，而不是 residual target。
- `L_tactile` 不向 detached boundary cache、PaliGemma 或 Action Expert 回传。
- `L_tactile` 能更新 Tactile Expert 与 late AnyTouch projector。
- AnyTouch backbone、projector 和 Tactile Expert 均有梯度。

### Inference

- 总计严格运行 10 个 Euler steps，dispatch 为 Action `6` + Tactile `4`。
- 6 步后时间为 `τ=0.4`，4 步后为 `τ=0.0`。
- boundary action KV 使用 `x_split, τ=0.4` 刷新。
- 每个 tactile step 不累计旧 tactile suffix cache。
- 最终输出是 Tactile Expert 积分结果，不额外加 residual。
- Action-only 10-step fallback 仍可运行。

### Data / serve

- lazy history 严格为 `[t-6,t-4,t-2,t]` 且不跨 episode。
- strict clip 的 shape、dtype、RGB 和 frame order 与当前 AnyTouch serving 一致。
- 不加入 offset 或 delay augmentation。
- 普通 vision、dual-SigLIP、旧 AnyTouch prefix checkpoint 不受影响。
